# Creighton Model FertilityCare (CrMS)

Source: [creightonmodel.com](https://creightonmodel.com/)

> Status: **shipped in v0.4**, stamp colours corrected in **v0.9** (B-2026-10-26-11).

The Creighton Model (CrMS) uses square stamps (red / green / white + baby), plus a **textual code** overlaid on each day's stamp (e.g. `8CK`, `10WL`). The codes are a compact alphanumeric grammar describing sensation + lubrication + color.

## Stamp colours (v0.9)

Rules from model-cervical-fluid `references/rules/method-rules.json`, `methods.creighton`, source: Creighton book (FR),
ch. 7 "Instructions de base", pp. 27-33. First matching rule wins:

| Codes | Stamp | Rule (status) |
|---|---|---|
| any code with `B` or `R` | red | `codeRules[0]`: blood seen with the mucus, charted as bleeding (literature) |
| `0`, `2`, `2W`, `4` | green | `codeRules[1]`: "2, 2W, 4 damp, wet, shiny without lubrication (the same meaning as dry)" (hds) |
| every other code (`6…`, `8…`, `10…`) | white + baby | `codeRules[2]`, `[3]` (hds); `stampNote`: "white with a baby for mucus; yellow stamps only in an instructor-led programme for continuous discharge (not used). Mucus days are fertile: the app never colours them yellow." |

Until v0.8, 2 / 2W / 4 and every 6 / 8 code without `L` were yellow ("non-fertile"), against the book
(`hdsDisagreements[0]`). No code draws a yellow stamp any more.

## Charted stamps (v0.14)

A stamp the person or her instructor put on a day (data-model 4.32.0, `fertility-cycles-chart-stamp`, `{ method, stamp }`)
is drawn in place of the one drawn from the code, with the code, the frequency and the peak mark or count on it, and also
on a day without a code. Only for `method: creighton`. The spec's `stamps`: red, green, green with a baby, white with a
baby, yellow, yellow with a baby. The last two are `onInstruction`: used only on the instructor's instruction, so a host
offers them only to a person who asked for them. Stamps are named by their colour, never by a meaning.

**Peak** (`peak`, hds): the last day of clear (`K`), lubricative (`L`) or very stretchy (`10`, 2.5 cm or more) mucus,
whatever the quantity (`codeRules[2]`); with a later return of peak-type mucus, only the last peak opens the count.
Marked **P**, then **1, 2, 3** (`fertileAfterOvulation.afterPeak`, hds). `8` is not peak-type (the book keeps
peak-type stretch for `10`; `references/creighton.md` disagrees, `hdsDisagreements[1]`).

**To confirm** (experts' worksheet, "Other open points", Creighton; E1–E4):
- `6CK`, `8CK` (partly clear, C/K) as peak-type (`gaps[1]`): left out of the peak candidates; `10CK` is in through its
  stretch.
- The shade of the `B` / `R` stamps (`gaps[2]`, book ch. 6 unread): kept red.
- The green-baby and yellow-baby stamps (`gaps[0]`): never drawn from a code, drawn where charted.
- How the HDS bleeding levels map to Creighton's H, M, L, VL, B (E2): every bleeding level is red.

## Visual primitives

Same palette family as Billings (see [billings.md](./billings.md)) with a few differences:

- Peak day is marked with **`P`** (not `X`).
- The frequency (`X1`, `X2`, `X3`, `AD`) is written under the code, inside the stamp (since 0.13.0,
  B-2026-11-23-9): `CellInput.frequency`, read from the shown record's `source.annotations.frequency`. A record from
  another method, or converted, has none.
- Text colour by contrast (0.13.0): white on the red stamps, dark on the white and green ones.

## Mucus options

Since 0.12.0 (plans 131, 134) the list is data-model's cervical-fluid converter v1 (data-model 4.23.0), generated by
model-cervical-fluid 1.3.0 (`tools/creighton-codes.mjs`) from the book's grammar `<base>[G|P][colour][L]`: **106
codes**, of which **95 are offered for entry** (the 36 codes of v0 keep their vectors; 11 of them are no longer
offered). Readers before hds-lib 2.60.0 keep v0, the 36 codes. The grid: [`../images/creighton-codes-grid.svg`](../images/creighton-codes-grid.svg)
(`npm run docs:images` reads the offered codes from the published pack).

- **Base**: sensation/lubrication class.
  - `0` dry · `2` damp · `2W` wet · `4` shiny · `6` sticky · `8` tacky · `10` stretchy · `PC`, `PY` pasty (no number).
- **Modifiers**: `G` gummy, `P` pasty; colours `C` cloudy, `CK`, `K` clear, `KY`, `Y` yellow, `B` brown, `R` red;
  `L` lubricative; `10DL`, `10SL`, `10WL` (damp, shiny, wet with lubrication).

The code is the most informative element on a Creighton chart — the color stamp alone doesn't disambiguate. So **the spec must always render the `code` text** (unlike Billings, where the stamp suffices).

## Mapping strategy

`ts/specs/creighton.ts` keeps no list of codes: `mucusRule` draws any code by rule on its text (case-insensitive) with
the code rules above, not from vectors. `mappingRules.mucus` holds only sample codes for previews and legends.

## Open choices

- **Long codes** (0.13.0): a code shrinks to fit the stamp, down to 0.2 of the cell, so `10GCKL` fits at 22 px but
  reads small there; a host can widen its days from `longestCode` (hds-webapp's cycle chart does).
- **Cyclefeminin pass-through codes** (`2`, `2W`, `10`) — already routed through Creighton on ingest by `bridge-cyclefeminin-net/src/converters/mucus.js`. No special display handling needed; they'll match `creighton/v0.json` directly.
